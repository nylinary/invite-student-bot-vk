# Настройка бота ВКонтакте — с нуля, для тех, кто работал только с Telegram

Инструкция ведёт от «нет аккаунта ВК» до «бот считает приглашённых в каждой беседе вуза».
Названия пунктов меню VK иногда двигает между версиями сайта: если путь не совпал слово
в слово, ищи по ключевому слову («Работа с API», «Настройки для бота»).

---

## 0. Шпаргалка: Telegram → VK

| Telegram | VK | Пояснение |
|---|---|---|
| Бот от @BotFather | **Сообщество** с включёнными сообщениями | В VK бот — не отдельный аккаунт, а страница сообщества, которая отвечает тем, кто ей пишет. |
| Токен бота | **Ключ доступа сообщества** | Кладётся в `VK_TOKEN`. |
| `t.me/your_bot` | `vk.me/<адрес сообщества>` | Ссылка, открывающая диалог с ботом. |
| Кнопка `/start` | Кнопка **Начать** | VK показывает её, когда человек впервые открывает диалог с сообществом. |
| Группа / супергруппа | **Беседа** | Групповой чат в мессенджере VK. |
| «Сделать бота админом с правом "Пригласительные ссылки"» | **Назначить сообщество администратором беседы** | В беседе VK у админа нет отдельных галочек прав — он просто админ. |
| Ник `@anya` | **Короткий адрес страницы**, например `vk.com/anya` | Используется в `ADMIN_IDS`. |
| Персональная ссылка-приглашение в чат | Персональная ссылка **на бота**: `vk.me/<сообщество>?ref=...` | В VK нельзя сделать свою ссылку в беседу на каждого человека. Подробнее в шаге 9. |

## 1. Аккаунт ВКонтакте

1. Зарегистрируйся на <https://vk.com>. Нужен номер телефона, иностранные номера подходят.
2. Узнай свой **числовой id**: открой свою страницу. Если в адресе `vk.com/id123456789`,
   то id — `123456789`. Если стоит короткий адрес вроде `vk.com/nikita`, его тоже можно
   вписать в `ADMIN_IDS`, а числовой id потом покажет команда `/id` в боте (шаг 7).

Каждому организатору, которому нужна админка, нужен свой аккаунт ВК.

---

## 2. Создать сообщество (это и есть «бот»)

Если сообщество у клиента уже есть — этот шаг пропускаем, дальше сразу 2а.

1. <https://vk.com/groups> → **Создать сообщество**.
2. Тип любой, подойдёт **Группа по интересам**. Название — по мероприятию,
   например «Студенческая вечеринка 26.09».
3. Задай **короткий адрес**: **Управление → Настройки** (блок «Адрес»), например `studparty26`.
   Ссылка на бота станет `https://vk.me/studparty26`. Адрес можно поменять и потом —
   бот считывает его заново при каждом запуске.
4. По желанию — аватар. Он же будет аватаркой бота в списке диалогов у студентов.

Ты владелец сообщества, поэтому всё дальнейшее тебе доступно.

## 2а. Если сообщество уже есть у клиента: какой доступ просить

Создавать новое сообщество не нужно — бот живёт в существующем. Владельцем остаётся клиент,
передавать сообщество не требуется.

**Проси роль «Администратор».** В VK пять ролей: Владелец (создатель), **Администратор**,
Редактор, Модератор, Рекламодатель. Только у администратора есть раздел **Управление**,
где лежат «Настройки», «Сообщения» и «Дополнительно → Работа с API» — всё, что нужно для шагов 3–5.
Редактору и модератору этот раздел недоступен.

Как клиенту это сделать: **Управление → Подписчики → Руководители → Назначить руководителя**
(в старом оформлении этот пункт меню называется «Участники»)
→ выбрать твою страницу → роль **Администратор** → сохранить. Отнять роль можно там же
в любой момент — например, после мероприятия.

Что это НЕ даёт клиенту потерять: владелец остаётся владельцем. Передача сообщества другому
человеку («Сделать владельцем») — отдельная операция, требует подтверждения и включённой
двухфакторной аутентификации; для бота она не нужна. Удалить сообщество администратор тоже
не может.

**Если клиент не готов давать даже администратора** — бот всё равно запустится. Тогда клиент
сам проходит шаги 3, 4 и 5 (лучше по видеозвонку с демонстрацией экрана) и присылает тебе
только **ключ доступа**. Больше ничего от него не нужно: ключ — это и есть все права бота.
Но учти: без роли администратора ты не сможешь ни проверить настройки, ни перевыпустить ключ,
если что-то пойдёт не так.

Ещё пара вещей, которые стоит проговорить с клиентом заранее:

- **Ключ создаётся из-под конкретного человека и подтверждается кодом из SMS.** Надёжнее,
  чтобы ключ выпустил владелец или постоянный администратор, а не тот, кого уберут из
  руководителей сразу после запуска.
- **Ключ = полный доступ к сообщениям сообщества.** Передавать его только в личку, не в общий
  чат, и не в переписку, которую потом не почистить. После мероприятия ключ удаляется одной
  кнопкой на той же странице.
- **Админка бота никак не связана с ролями VK.** Чтобы пользоваться `/admin`, человеку не нужна
  никакая роль в сообществе — достаточно, чтобы его id стоял в переменной `ADMIN_IDS` (шаг 6).
  Наоборот тоже верно: администратор сообщества без записи в `ADMIN_IDS` админку не увидит.
- **Роль в сообществе не даёт никаких прав в беседах вузов.** Чтобы подключить беседу (шаг 8),
  нужно быть администратором именно этой беседы — это обычно куратор вуза, а не клиент.

Проверяется за минуту: получив роль, открой **Управление → Дополнительно → Работа с API**.
Если пункта «Дополнительно» или вкладки «Работа с API» в меню нет — значит, выдали роль ниже
администратора (редактор, модератор) либо в этом сообществе раздел доступен только владельцу.
Тогда ключ выпускает владелец и присылает тебе (вариант выше).

## 3. Включить сообщения и возможности ботов

1. **Управление → Сообщения** → **Сообщения сообщества: Включены**.
2. **Управление → Сообщения → Настройки для бота** — это отдельный подпункт в левом меню,
   прямо под «Сообщениями». Именно там (а не на странице с ключами API):
   - **Возможности ботов: Включены**;
   - **Добавить кнопку «Начать»: включено**. Обязательно: именно нажатие «Начать» приносит
     боту метку `ref` из личной ссылки — без кнопки друг должен сам что-то написать,
     и часть приглашённых потеряется;
   - **Разрешать добавлять сообщество в чаты: включено**.
     Без этого бота не получится добавить в беседы вузов. Если этой галочки там нет,
     посмотри в разделе **Чаты** — VK переносил её между экранами.

Бот пытается включить это сам при запуске (шаг 5), но включи руками — это минута.

## 4. Создать ключ доступа (аналог токена)

1. **Управление → Дополнительно → Работа с API → Ключи доступа → Создать ключ**.
   На этой странице три вкладки: «Ключи доступа», «Callback API», «Long Poll API».
2. Отметь права (VK называет их так):
   - **управление сообществом** — чтобы бот сам включал свои настройки;
   - **сообщения сообщества**;
   - **фотографии** — для рассылок с картинкой;
   - **файлы** (бывшие «документы») — для выгрузок CSV.

   Если в сообществе уже висят чужие ключи (Senler, рассылки и прочее) — не трогай их,
   просто создай ещё один, свой. Ключи друг другу не мешают.
3. Подтверди (VK пришлёт код по SMS или в приложение). Скопируй ключ, он начинается
   с `vk1.a.` — это `VK_TOKEN`. Относись к нему как к токену телеграм-бота: нигде не публикуй.

Если ключ утёк: удали его на той же странице, создай новый и обнови `VK_TOKEN`.

### Если пункта «Работа с API» нигде нет

Проверь по порядку:

1. **Пролистай страницу «Дополнительно» до самого низа.** Блоки там идут подряд: «Общее»,
   «Возрастные ограничения», «Интеграции», «RSS» и дальше. Раздел с ключами может быть
   ниже видимой части экрана.
2. **Посмотри, кто ты в сообществе:** Управление → Подписчики → **Руководители**. Если рядом
   с твоим именем стоит «Администратор», а не «Владелец» — скорее всего дело в этом: доступ
   к ключам VK нередко оставляет только создателю сообщества.
3. **Тогда ключ выпускает владелец.** Пусть он пройдёт шаги 4.1–4.3 у себя (можно по
   видеозвонку) и пришлёт ключ в личку. Для бота этого достаточно: ключ и есть все его права,
   никакой роли в сообществе боту не нужно.
4. Если владелец тоже не находит раздел — ключ сообщества можно получить через OAuth
   (implicit flow, `oauth.vk.com/authorize` с `group_ids` и нужными правами). Способ рабочий,
   но требует своего приложения VK ID — напиши, разберём отдельно.

## 5. Включить Long Poll (так бот получает события)

Это аналог поллинга, на котором работает телеграм-версия.

**Управление → Дополнительно → Работа с API → вкладка Long Poll API**
(та же страница, где создавали ключ):

- **Long Poll API: Включён**;
- **Версия API: 5.199**;
- вкладка **Типы событий**:
  - **Входящее сообщение** (`message_new`),
  - **Действие с сообщением** / событие callback-кнопки (`message_event`).

Всё это бот включает сам при старте, если у ключа есть право «Управление сообществом».
Если в логах появилось `Не смог сам включить Long Poll` — выставь галочки руками.

## 6. Деплой на Railway

Так же, как в телеграм-проекте.

1. В Railway: **New project** → добавить **PostgreSQL** → добавить сервис из этого репозитория
   (или `railway up` из папки проекта). Команда запуска уже прописана в `railway.json`:
   `python -m app.main`. Публичный порт и домен боту не нужны.
2. Переменные сервиса:

   | Переменная | Значение |
   |---|---|
   | `VK_TOKEN` | ключ из шага 4 |
   | `ADMIN_IDS` | организаторы через запятую: id и/или короткие адреса, например `123456789, nikita` |
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
   | `ORGANIZER` | контакт для студентов в текстах бота, например `vk.com/nikita` (по умолчанию там телеграм-ник, поменяй) |

   `GROUP_ID` задавать не нужно — бот определит сообщество по ключу.
3. Задеплой и открой логи. Нормальный старт выглядит так:
   ```
   Список вузов перенесён в базу: 43 шт.
   Запускаю vk.me/studparty26 (club123456): 43 вузов, админов 2 ...
   ```
   `VK_TOKEN не задан` или `[5] User authorization failed` — ключ не прописан или неверный.

**Бот должен работать в одном экземпляре.** Если он запущен на Railway, не запускай его
параллельно у себя с тем же ключом: обе копии будут читать одни и те же события и отвечать дважды.

## 7. Первая проверка в личке

1. Открой `https://vk.me/<твой адрес>` → нажми **Начать**. Бот здоровается. Так как ты
   в `ADMIN_IDS`, рядом будет кнопка **🛠 Админка**.
2. Отправь `/id` — бот пришлёт твой числовой id. Если в `ADMIN_IDS` был короткий адрес,
   надёжнее заменить его на этот номер: адрес человек может сменить.
3. Отправь `/admin` — откроется админка.
4. Отправь `ИТМО` — бот ответит «Беседы этого вуза пока нет», потому что беседы ещё не
   подключены. Так и должно быть.

## 8. Подключить беседу вуза

Это делается один раз на каждую беседу. Тот, кто делает, должен быть **администратором
этой беседы** (обычно куратор, который её создал).

1. **Добавить бота в беседу.** Страница сообщества → кнопка **Добавить в беседу** под обложкой
   → выбрать беседу вуза. (Кнопка появляется, только если включён пункт из шага 3.)
2. **Назначить администратором.** В беседе: нажать на название беседы → **Участники** →
   найти сообщество → **⋯ → Назначить администратором**.
   Без этого VK не отдаёт боту ни ссылку-приглашение в беседу, ни список участников,
   ни название беседы — считать будет нечего.
3. **Привязать к вузу.** Отправить в беседе:
   ```
   /bind itmo
   ```
   `/bind` без аргумента выводит список всех ключей. Ключи лежат в `universities.json`:
   `itmo`, `guap`, `leti`, `spbgu` и так далее.
   Бот ответит «✅ Беседа привязана к вузу …» и опубликует объяснение для студентов
   с кнопкой **🔗 Получить свою ссылку**. **Закрепи это сообщение** в беседе.

**Общая беседа без вуза** (например, общий чат мероприятия) подключается командой
`/bindchat Общий чат`, и ей **не нужны права администратора** — достаточно, чтобы сообщество
было в беседе участником, которому не запрещено писать. Это удобно: VK показывает пункт
«Назначить администратором» не всем (иногда только создателю беседы). Она будет получать рассылки из админки, но в статистике по
вузам не появится, и студентам её как вуз бот не предложит.

Полезное:
- Если в **названии** беседы есть вуз («ИТМО | беседа»), бот узнает его ещё на шаге 1 и сам
  подскажет в беседе, какую именно команду `/bind …` отправить после выдачи прав.
- Если название ни на что не похоже, бот в этой беседе молчит и пишет организаторам в личку.
  Так сделано специально: бота могут добавить куда угодно, в том числе по ошибке.
- `/bind`, `/unbind` и `/announce` доступны не только из `ADMIN_IDS`, но и администраторам
  самой беседы — куратору не нужен доступ ко всей админке.
- `/announce` заново публикует объяснение для студентов — например, если закреп потерялся.
- Обычную переписку в беседах бот не читает: только команды и события о вступлениях и выходах.

Когда подключишь несколько бесед: `/admin` → **🔍 Проверить привязки**. Бот обойдёт все
привязанные беседы и проверит, что беседа на месте, её название совпадает с вузом
и бот всё ещё администратор.

## 9. Как это выглядит у студентов (и чем отличается от Telegram)

В Telegram бот делал каждому студенту свою ссылку-приглашение в чат. **В VK так нельзя:**
у беседы одна общая ссылка, и VK не сообщает, кто кого по ней позвал. Поэтому:

1. Студент пишет боту название вуза и получает **(а)** ссылку на беседу вуза
   и **(б)** свою личную ссылку — она ведёт **в бота**:
   `vk.me/studparty26?ref=r<его id>_<вуз>`.
2. Он кидает личную ссылку друзьям.
3. Друг открывает её → открывается диалог с ботом → друг нажимает **Начать** → бот запоминает,
   кто его позвал, и сразу присылает ссылку на беседу этого вуза.
4. Друг вступает в беседу → бот засчитывает приглашённого студенту и присылает ему «🎉 …».

То есть приглашённый засчитывается, только если друг **пришёл по личной ссылке и потом вступил
в беседу**. Тот, кто вступил по общей ссылке на беседу, найденной где-то ещё, не засчитывается
никому. Если участник беседы добавил друга в неё вручную — приглашённый засчитывается тому,
кто добавил.

Всё остальное как в Telegram: вышедшие из беседы перестают засчитываться, массовый залив
купленных аккаунтов отсеивается, билеты выдаются от 5 / 25 / 50 приглашённых.

## 10. Что есть в админке

`/admin` в личке (или кнопка **🛠 Админка**):

- **📊 По вузам** — по каждому вузу: выдано ссылок · вступило всего · по реферальным · сейчас в беседе;
- **🏆 Топ пригласивших**, **👤 Участники** — выборка по числу приглашённых (`5-25`, `10+`, `<5`);
- **🎫 Билеты** — включает и выключает у студентов кнопку «Получить билет» (по умолчанию выключена).
  На входе коды проверяются командой `/ticket NS-XXXXXX`;
- **🚨 Накрутка** — кто попал под детектор и кого можно вернуть в зачёт вручную;
- **📣 Рассылки** — пост во все или выбранные беседы, сообщение пользователям бота,
  сразу или по расписанию (время московское);
- **🎓 Список вузов** — добавить вуз, переименовать, задать алиасы. Пункт **🔗 Ссылка** — это
  запасная ссылка на беседу, которую бот отдаёт, пока беседа не подключена. Сейчас она пустая
  у всех вузов: в оригинале там были телеграм-ссылки, в VK они бесполезны;
- **📥 Выгрузить CSV** — все вступления файлом в диалог.

## 11. Боевая проверка на 10 минут

Код проверен на поддельном VK API. Перед запуском стоит один раз проверить на живом VK
**с двух аккаунтов** (твоего и друга):

1. Создай тестовую беседу «ИТМО тест». Добавь бота, назначь администратором, отправь `/bind itmo`.
   ✅ Бот подтвердил и опубликовал объяснение.
2. Со своего аккаунта напиши боту `ИТМО`. ✅ Пришли ссылка на беседу и личная ссылка `vk.me/...?ref=...`.
3. Друг (ещё не в беседе) открывает твою личную ссылку и нажимает **Начать**.
   ✅ Бот сразу прислал ему ссылку на беседу ИТМО.
4. Друг вступает в беседу по этой ссылке. ✅ Тебе пришло «🎉 По твоей ссылке … вступил(а) …»,
   а `/stats` показывает 1.
5. Друг выходит из беседы. ✅ `/stats` показывает 0 и «вышли из беседы: 1».
6. `/admin` → **📊 По вузам** показывает число участников беседы.

Если не сработал шаг 3 или 4 — пришли логи Railway за это время. Именно эти места зависят
от поведения VK, которое можно подтвердить только на живом запуске.

После проверки отвяжи тестовую беседу командой `/unbind`.

## 12. Что делать, если не работает

| Симптом | Причина и что сделать |
|---|---|
| Бот вообще не отвечает в личке | Сервис не запущен (смотри логи Railway); выключены сообщения сообщества (шаг 3); выключен Long Poll или не отмечено «Входящее сообщение» (шаг 5); у ключа нет права «Сообщения сообщества» (шаг 4). |
| Кнопки крутятся и ничего не делают | В типах событий Long Poll не отмечено «Действие с сообщением» (шаг 5). |
| На странице сообщества нет кнопки «Добавить в беседу» | Выключено «Разрешать добавлять сообщество в беседы» (шаг 3). |
| `/bind` → «Сначала назначьте меня администратором беседы» | Шаг 8.2: назначь сообщество администратором беседы. |
| `/bind` ничего не делает | Ты не в `ADMIN_IDS` и не администратор этой беседы. Либо сообщение не начиналось с `/`. |
| `/admin` ничего не делает | Твоего id или адреса нет в `ADMIN_IDS` (проверь `/id`), либо переменная не сохранена и не передеплоена. |
| Друг вступил, но не засчиталось | Он не открыл личную ссылку и не нажал «Начать» до вступления. Либо открыл ссылку на другой вуз. Либо вступил по общей ссылке, взятой где-то ещё. |
| Каждый ответ приходит дважды | Запущены две копии бота с одним ключом (шаг 6). |
| В логах `Не смог сам включить Long Poll…` | У ключа нет права «Управление сообществом». Не страшно, если шаги 3 и 5 выставлены руками. |
| В логах `[5] User authorization failed` | Ключ неверный или удалён. Создай новый и обнови `VK_TOKEN`. |
| Выгрузка CSV: «Не получилось загрузить файл» | У ключа нет права «Документы». |
| Рассылка с картинкой: «Не получилось загрузить картинку» | У ключа нет права «Фотографии». |
